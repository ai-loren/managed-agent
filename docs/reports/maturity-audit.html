核心问题

和一个成熟参考平台对齐了吗?

一个生产可信的核心,还不是一个成熟的平台——完成约四分之三,且对剩下的四分之一诚实。

已经对齐的是最难、最安全攸关的地基:沙箱隔离、密钥处理、模型网关、会话/运行时生命周期、以及治理层(版本、权限、记忆信任边界、产物)。这些真的建好了、可达、且已针对真实攻击场景加固。一个单版本、单会话、工具受限的 agent 今天就能端到端安全运行。

距离"成熟平台"还差三件在成熟阶段属于标配的事,目前在生产里是部分或缺失:可扩展性(装不了 skill、起不了 MCP server)、知识检索(文档能进、运行中的 agent 取不回来)、韧性与连续性(沙箱丢失恢复接线了却不触发、上下文不可恢复、无热升级、warm 复用未端到端落地)。

结论清单

还差什么 · 已经很强的是什么

最重要的剩余缺口(按重要性)

  1. 工具/skill 可扩展性未端到端接线 —— 生产里装不了第三方工具,MCP 只有 schema 无 launcher。对 agent 平台是头等能力。
  2. RAG 检索运行中不可达 —— 检索工具只在 agent-core 从不调用的 buildToolset 里注册;文档能进,agent 取不回。
  3. 沙箱丢失恢复在生产是死代码 —— 组合根 onSandboxReap 返 void,recoverLostSandboxes 从不触发;租约和 reaper 真实,但自愈没接上。
  4. 无热升级 / 无可 rebind 的 core —— 会话进程钉死一个版本,同时挡住了 warm 复用落地和上下文恢复。
  5. 文件凭证 & 审计完整性 —— file 凭证被当 env var 注入;2 个审计事件类型从不产出;审计从不清扫。

真正交付且已加固的强项

  1. 运行时/会话核心真实可达 —— driver 真的拉起 agent-core:轮次循环、工具分派、协作中断、序列精确 SSE 恢复、独立租约、终态保证。
  2. 沙箱隔离与出口安全 —— 容器 driver + 真实 k8s driver(非 root、无 SA token、secretKeyRef、逐 Pod NetworkPolicy);出口无法强制则拒绝。
  3. 凭证处理与模型网关 —— 信封加密、AAD 绑定、只写交换带原因/审计;网关有目录/白名单/用量成本。
  4. 治理原语 —— 不可变版本 + CAS;每次工具调用求值的权限引擎;构造上成立的记忆信任边界;内容寻址产物;独立源签名预览。
  5. 触发入站 + 类型化 SDK —— 重放受限的 webhook HMAC、DST 正确的零依赖 cron、序列游标流恢复。

方法论

这个数字为什么可信

这不是自我打分。5 个独立 agent 各领一个能力域,读真实实现代码(不是读文档),对每项 delivered/partial/missing 声称裁定"诚实 / 乐观 / 悲观",附 file:line 证据,再由第 5 个 agent 综合。

裁定标准刻意严格:一项只有存在真实、可达的代码路径才算 delivered —— 单测覆盖但无生产 caller 的代码算乐观。这个仓库有明确的"测试齐全却不可达"历史(runtime bridge 曾完全单测覆盖却因无人调用 bind() 而在生产不可达),所以这条标准正中要害:5 项乐观全属此类。

诚实度 40/5/0、零悲观、零掩饰,本身就是这个项目工程质量的一个信号——文档罕见地如实。
